# AI 整体部件识别、分色与多家具验收

日期：2026-11-13。[图片与证据总览](../experiments/semantic_parts_20261113/index.html)。[皮质沙发演示](http://127.0.0.1:8001/?job=dbac18425968413681567e1d5500de2d)。

## 当前结论

已将“自动识别完整部件并分色”接入工作台：六视角观察、文字定位、自动分割、跨视角实例合并，再按整组选择和换材质。用户无需先逐个点击或涂抹提示点。同一靠枕的正反面不应变成两件，底层面片也不再直接充当部件数。

**本轮改善了整体表面分组，没有完成准确实体拆分。** 两款沙发的主要靠枕归组比旧的薄片切割更合理，但坐面和主体还没有可靠分开；原始粘连模型的隐藏接口没有补齐。通用家具识别、完整独立坐垫及实体拆装仍未通过质量验收。三个演示的编辑版本保留 unreviewed，没有将软件测试通过当成商品级验收。

## 1. 为什么原来会拆得那么碎

之前的主要依据是可见表面、法向、连通片和切割范围。这些能找到几何区域，但“一个平面片”“一个颜色区域”和“一个真实靠枕”不是同一回事。单个可见面也无法说明其厚度和接触面，因此会得到薄片、靠枕与坐垫粘连，或同一部件前后被拆开。

本轮把完整实例作为清单和材质编辑单位。一个实例可以包含多个可见面片和多个底层网格；它们共用 logical_group_id 和分色，不因为面片数增加就增加部件数。仍不确定的区域继续如实处理，不能靠强制填满预设数量来冒充识别。

## 2. 实际使用的 AI 与几何方法

1. 本地 Blender 为源模型渲染六个有相机标定的视角，同时输出 16 位距离图。
2. **Grounding DINO Tiny** 用 pillow / seat cushion 等文字提示寻找软包实例候选；未知品类先检测家具类型，不再默认套为沙发或书柜。
3. **SAM 2.1 Hiera Tiny** 根据检测框及自动生成的点产生掩码。这里的点由程序提出，测试没有用户逐件涂选。模型预测分数不是实际准确率。
4. 将掩码通过相机矩阵对应回源模型三角面，并用距离图排除被遮挡的面。跨视角合并同一实例；互不相交的同视角观察用于阻止把邻近靠枕误合并。
5. 检查相反表面的观察视角、朝向和投影重叠，合并同一个靠枕的正反面。沿网格表面在有限范围内传播归属，清理颜色碎点；未观察归属与实际观察在记录中区分。
6. 圆柱抱枕不直接相信文字标签：使用主轴、法向约束和圆截面稳健拟合检查圆柱证据。只有圆周覆盖、侧面积和长度条件足够时才命名为圆柱抱枕；扁平靠枕背面重新分配给邻近靠枕。该检查仍是几何启发式，不是新的识别精度证明。

全部复用本机已有模型，不需要商业 API 密钥；没有新训练模型、下载新权重或将图片上传外部服务。本轮没有改变图生 3D 引擎，也没有修复源模型的形变。

## 3. 新的操作方式

在模型右侧点击 **AI 自动识别并分色**。系统显示观察视角、AI 识别、合并分组等实际阶段；识别完成前不改当前版本。结果在弹窗中查看，避免同时摆放两个可编辑主视图。

点击部件名称或模型选择整组，可以隔离查看背面、底面并拖动旋转。点击“采用 AI 整体分组”保存独立版本，然后直接选择“靠枕 / 圆柱抱枕”等整组换材质。

“显示整体部件分色”是显示方式，**不会把诊断颜色保存成原材质**。开始调材质时自动退出分色，避免真实材质效果被覆盖。同一个逻辑部件中的所有底层网格一起选中和修改；涂抹和人工修正仍保留作补救。

后台识别有阶段、失败状态和超时；重复相同输入复用已有候选。短暂网络断开后继续读取进度，服务重启则把中断的识别明确标为失败，允许重试，不继续无限显示等待。采用候选前检查源版本、文件 SHA-256 和候选文件，旧源模型不能直接套用旧结果。

## 4. 两款沙发的看图验收

皮质沙发：最终 3 组为 靠枕 1、坐面与主体 1、圆柱抱枕 1。正面和背面分别检查；早期圆柱候选混入普通靠枕背面，已用形状证据重新归属。当前仍有少量接触边界误差，三组都没有恢复真实内部接合面。界面实测选整组圆柱抱枕换成青绿色，其余两组原材质签名不变，并完成浏览器下载。

灯芯绒沙发：最终 6 组，含 5 个靠枕和主体。早期同一靠枕正反面被算为两组，已合并；单视角的细碎候选不再直接算成新部件。分色图仍可见靠枕附近的边界串色，且坐面、扶手、底座没有分开，因此**不判定为完整坐垫拆分通过**。

椅子：本轮两个候选只说明分组和编辑流程可运行，“靠枕”的语义并未验证为真实独立零件。圆桌：无效的整件桌面候选被拒绝。不能只挑成功的沙发截图来宣称任意家具都适用。

本轮没有人工逐面真值、实例标注或照片相机匹配，因而没有分割准确率、照片相似度或真实装配精度数据。渲染按对象范围归一化显示，不能用截图像素比较真实尺寸。

## 5. 验证数据

- **123 项 Python 测试通过**：API / 合同 58，几何 / 部件 / 结构 65。新增覆盖深度遮挡、同视角实例冲突、靠枕正反面合并、邻近靠枕不误合并、圆柱与扁平面的区分、原属性与三角面保留、无效整件桌面拒绝、队列去重、过期结果拒绝与重启中断恢复。
- **5 项分色 / 材质状态检查通过**：同组同色、不同组区分、源材质不变、关闭恢复、材质草稿优先。
- **11 个逻辑组逐组验证**换材质、移动、单独导出；其他组逐三角面坐标和材质签名保持不变。源模型 POSITION / NORMAL / UV 等现有属性字节及全部三角面归属保留，原生成文件 SHA-256 不变。
- **32 份 GLB 文件**完整 glTF Validator 校验，0 错误、0 警告。包含装配、移动、导出和诊断文件，不等于 32 个独立家具。
- 独立导出中 **0/11 闭合**。这个结果直接说明它们仍是表面分组，不能因 GLB 合法而声称已经完成实体零件重建。
- **56 张交付诊断渲染**，包括三个候选的全组、单组、正侧背底面。六视角输入及所有掩码保留在各任务 semantic_scans 下。
- 真实浏览器覆盖后台识别、整组选择 / 隔离、弹窗开关、390px 宽度、采用分组、分色不改变材质、整组圆柱抱枕局部材质和下载。最终三份演示的分组清单及 unreviewed 状态也在浏览器复核。
- 前端类型检查和生产构建通过，已有主包大于 500kB 的提示仍存在。

## 6. Review 与修正记录

识别层发现并修正了：文字“圆柱抱枕”误指普通靠枕、跨视角正反面重复、圆柱与扁平靠枕背面混组、散落颜色碎点，以及整张圆桌被叫作桌面。源模型和候选只读，未采用前不写 current_asset_version；采用后仍保留历史版本。

界面实测发现全局 Viewer 高度覆盖弹窗局部高度，画布挡住部件按钮；已用作用域样式修复，未强制点击绕过。第二次测试在 React 状态更新前检查分色开关，改为等待实际状态更新，并从已保存版本继续完成材质与导出验证。ui_results_initial / ui_results_material_race / modal_debug 及原日志保留，最终 ui_results 明确记录了继续执行的来源。

浏览器首轮还注入了一次真实轮询请求失败，之后恢复到识别预览；这是连接恢复测试，不是新的识别数据。渲染预研曾遇到 Blender 相机 API 和相对输出路径问题，已修正；服务使用绝对路径及 Python 非零退出码检查。初次日志保留。

最终自动化表面分组的请求、模型版本、观察掩码、形状证据和文件校验都可追溯。尚有边界误差，不把自动候选数、面数增加或 API 200 当作语义质量验收。

## 7. 未完成的项目质量目标

本轮解决了“每一个小面片都像一个部件”的主要交互和归组问题，但项目还不能认定优化完毕。后续最明确的两项是：准确区分坐面与固定扶手 / 底座，以及为已确认的整体部件补齐可检查的隐藏接口。完整坐垫、靠枕实体闭合、任意家具语义准确拆分与真实制造结构仍未达标。
