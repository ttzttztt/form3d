# 模型选型与官方资料核验

核验日期：2026-11-10。本文给出适合开展试验的候选，不宣称已经覆盖当日所有最新模型，也不做未经实测的效果排名。最终采购或部署应固定具体版本并在真实商品集上比较。

2026-11-11 实测补充：Hunyuan3D-2mini 标准形状模型已在本机通过实际 CUDA 推理并接入为几何实验选项。统一灰模对比显示两张干净输入有改善，复杂背景扶手椅输入分割失败；本轮没有生成纹理，完整商品外观未通过验收。参数、真实耗时、失败尝试和证据见 [质量验收记录](reviews/QUALITY_ACCEPTANCE_2026-11-11.md)。

## 当前已部署：TripoSR 本地图生 3D

已根据无商业密钥、Windows 和 RTX 3060 Laptop 6 GB 的当前条件，部署并实际运行 [TripoSR 官方模型](https://huggingface.co/stabilityai/TripoSR) 和 [官方源码](https://github.com/VAST-AI-Research/TripoSR)。这是本机可运行的基础方案，不代表模型效果排名。

最终网页验收记录位于 `.data/checks/local3d-validation/result.json`：两张不同输入均自动推理、导出并通过 GLB 完整校验，进入待审核；无聊天建模介入。造型桌实测 43.59 秒、105,672 三角面；官方椅子示例实测 65.41 秒、47,100 三角面。均采用 192³ 网格采样，PyTorch 分配显存峰值约 2,587 MiB，不含系统/浏览器等显存。检测排队及系统负载会增加端到端等待时间。

验证覆盖网页提交、真实 CUDA 推理、不同输入产生不同模型、去背景、输入证据、GLB 下载、取消后释放显卡队列、刷新恢复及移动端布局。另有 17 项 API/流程测试和 4 项图片准备、颜色及 Windows 文件竞争回归检查。

当前输出为单网格和预测顶点颜色，尚无独立 PBR 贴图。复杂造型、浅色边缘、细杆、镂空、背面及尺寸仍需审核；真实图片的外观质量需逐品类评测。白底图使用边缘连通背景分离，避免通用去背景模型吞掉浅色桌面；透明图优先保留原 alpha。

## 1. 选型策略

第一轮每个关键步骤只保留少量候选：

- 目标选择/抠图：交互式分割为基础；需要按文本找家具时增加检测/定位模型。
- 图像编辑：仅在遮挡或倒影确实影响建模时调用，优先局部修改。
- 图生 3D：在一个商业 API 与一个适合自身条件的自部署方案之间开展对比；预算不足时先评测一个可用 API。
- 参数化几何、规范化与导出：复用 Blender 能力。
- 最终预览：实际目标 Three.js 查看器；文件结构检查使用 glTF Validator。

图生 3D 是最先验证的核心风险。不要在还不知道目标品类能否生成可接受模型前，先搭齐全部模型基础设施。

## 2. 候选及边界

| 环节 | 候选 | 应验证的能力 | 不应假设的能力 |
| --- | --- | --- | --- |
| 目标定位 | Grounding DINO 与 Grounded SAM 2 流程 | 文字定位家具、候选框质量、细小部件保留 | 自动理解所有配件归属，或可靠恢复被挡住的边界 |
| 交互分割 | SAM 2/2.1 等具体可部署检查点 | 点击/框提示、细腿、孔洞、白色边缘 | SAM 2 单独接收任意文本并理解“去掉猫” |
| 图片编辑 | Qwen-Image-Edit、FLUX Kontext 等候选 | 局部遵循、结构保真、掩码外变化、纹理保持 | 编辑后不可见区域变成真实依据 |
| 商业图生 3D | Tripo、Meshy 等候选 API | 家具效果、薄结构、PBR、输出格式、异步任务、单件交付成本 | 所有套餐与版本都有相同功能、价格、商用与数据条款 |
| 自部署图生 3D | Hunyuan3D 的具体适用版本及其他候选 | GPU/系统兼容、目标品类表现、吞吐和许可适用性 | 家族中各版本的资源需求和许可一致 |
| 几何/处理 | Blender | 结构模板、坐标尺度、材质、GLB 导出 | 自动从任意商品照片读取完整参数 |
| 结构验证 | Khronos glTF Validator | 文件结构、属性和资源问题 | 判断模型是否真的像商品 |

在 SAM 2 流程中，文字定位需要额外的检测/定位环节，或者让用户通过框与点击提供提示。可见物体分割与遮挡后的完整形状估计是不同任务。

## 3. 本次成功核验的官方资料

### SAM 2

官方仓库：[facebookresearch/sam2](https://github.com/facebookresearch/sam2)。

本次成功读取官方 README，确认：

- 支持图像和视频中的提示式分割，仓库列有 SAM 2.1 检查点。
- README 要求 Python ≥3.10、PyTorch ≥2.5.1、torchvision ≥0.20.1；实际部署固定兼容版本。
- README 声明模型检查点、训练代码和 demo 代码使用 Apache 2.0，同时列有字体及可选组件的独立许可。

以上仅适用于实际核验的仓库内容；使用其他分割模型时重新检查其自身要求。

### Grounded SAM 2

官方仓库：[IDEA-Research/Grounded-SAM-2](https://github.com/IDEA-Research/Grounded-SAM-2)。

本次成功读取官方 README，确认其将 Grounding DINO 等定位能力与 SAM 2 结合，并包含不同检测后端的使用路径。其依赖和 API 后端应分别检查；采用组合项目不意味着全部组件有同一份许可或安装要求。

### Hunyuan3D-2

官方仓库：[Tencent-Hunyuan/Hunyuan3D-2](https://github.com/Tencent-Hunyuan/Hunyuan3D-2)。

本次成功读取官方 README，确认其区分形状生成和纹理生成，并给出多视角和低显存等使用路径。README 列出的资源参考是形状生成约 6 GB 显存、形状与纹理合计约 16 GB；这些数字不是本项目实测峰值，也不能推广到其他 Hunyuan3D 版本、分辨率和部署方式。

本次也成功读取该仓库的 [LICENSE](https://github.com/Tencent-Hunyuan/Hunyuan3D-2/blob/main/LICENSE)。它是 Tencent Hunyuan 3D 2.0 Community License Agreement，含适用地域等条件；文本明确排除了欧盟、英国和韩国。不能简单把“可获取权重”理解为在所有地域、所有用途下不受限制地商用。选定版本与部署/服务范围需要匹配该版本条款。

本文只核验上述具体仓库，不把 2.0 的条款或资源需求推定给其他版本，也不因此宣称 2.0 是当前最新或最佳方案。

### glTF

官方规范：[glTF 2.0](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc)。本次成功读取规范页面。

实现时按规范检查米制单位、右手坐标和 Y 向上约定。使用金属/粗糙度 PBR 及需要的透射等扩展时，在目标查看器验证支持情况。规范合规与实际商品外观正确分别验收。

校验工具候选：[KhronosGroup/glTF-Validator](https://github.com/KhronosGroup/glTF-Validator)。本次未单独读取该工具的实现与安装说明，接入时确认具体版本。

## 5. 统一评测方法

### 对同一批商品做成对比较

1. 使用相同原图、目标选区、允许的补充信息和交付标准。
2. 分别评测原图输入、只抠图、必要修补后的输入，确认清理是否带来净收益。
3. 第一轮每条路线只生成一个候选；追加候选另计预算与通过率。
4. 所有结果走相同的规范化、查看器和人工审核流程。
5. 记录模型 ID、版本、配置、seed、耗时、费用、人工分钟与失败原因。
6. 人工审核尽量隐藏供应商名称，减少品牌印象影响判断。

不强求不同 API 使用完全相同的分辨率或内部参数；采用各自官方推荐配置，同时统一总预算和交付标准，并记录差异。

### 比较维度

| 维度 | 记录方式 |
| --- | --- |
| 目标与结构 | 是否混入背景、支腿数量、孔洞、板件、扶手与软垫 |
| 外观 | 真实可见部分相似度、材质、文字、光影与接缝 |
| 不可见面 | 合理性与生成缺陷；缺少实拍时不宣称正确性 |
| 可编辑性 | 部件是否可分、UV 是否可用、材质是否可替换 |
| 资源 | 三角面、纹理、文件体积、浏览器加载表现 |
| 稳定性 | 技术失败、超时、输出不完整、后端波动 |
| 成本 | 总费用、返工次数、人工分钟、最终通过资产数 |
| 接入条件 | 版本固定、幂等、取消、数据策略和使用范围 |

### 确定方案前应具备的记录

- 候选方案在目标 SKU 与留出集上的结果，而非只展示官方精选样例。
- 具体 API/权重版本、代码或镜像版本、模型配置与依赖记录。
- 已知不支持的结构与材质；拒绝、补图、降级或人工处理策略。
- 实际可接受的交付成本及处理耗时分布。
- 供应商计费、数据保留和所选模型使用条件的核验结果。

第一版优先选择“对目标商品稳定、失败可解释、单件交付成本可接受”的路线，再逐步替换模型或扩大能力范围。
