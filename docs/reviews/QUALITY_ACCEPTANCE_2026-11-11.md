# 本地模型质量升级与验收记录

日期：2026-11-11。验收人：助手对实际导出 GLB 的渲染结果进行目视检查；没有代替用户完成最终审核。

结论：Hunyuan3D-2mini 在两张干净输入上表现出实际几何改善，但本轮**完整商品模型未通过验收**。椅子示例的几何可试用；造型桌的三眼完整外观仍未验收；场景扶手椅因抠图丢失靠背而失败。没有运行纹理生成模型，不把灰模算作完整商品资产。

## 已完成的工作

- 独立安装 Hunyuan3D-2mini 标准形状模型并接入工作台，保留 TripoSR 快速彩色方案。新增选项明确标为“几何实验”，不自动替换默认方案。
- 在同一台 RTX 3060 Laptop 6GB、16GB 内存机器上，重新生成三张 TripoSR 基线和对应 Hunyuan 候选，保留原始选区、共同前景、模型、参数、哈希、日志和失败尝试。
- 从真实 GLB 渲染统一中性灰材质的正、斜、侧、后视图。只做等比例展示归一化，不修模型，不用 AI 修图替代结果，也没有拟合照片相机。
- 跑通网页选择 Hunyuan → 实际 CUDA 推理 → GLB 校验 → 预览 → 下载 → 刷新恢复 → 移动端检查。该流程测试通过不代表商品外观合格。

耗时为脚本内计时，包含依赖导入、权重加载、图片准备、推理和导出，不含下载、API 排队和离线渲染。显存是 PyTorch 分配统计，不是整卡总占用；RSS 是每 100ms 采样的进程工作集，不是整机内存。三次相同的分配显存峰值来自各自运行记录，不是估算。本轮样本很小且系统负载不同，不据此宣称普遍速度或显存优势。

参数：Hunyuan 标准 mini、30 步、seed=42、256³ 网格、组件 CPU 卸载；DINO 图像编码器 BF16，DiT/VAE FP16；使用完整网格查询和 CPU marching cubes。没有偷偷换成 Turbo 权重。TripoSR 保持原有 192³ 配置。

三个 Hunyuan GLB 均通过文件检查，校验错误和警告均为 0。即使场景扶手椅的网格闭合、文件有效，它仍未通过外观验收——文件检查、面数和闭合性都不能证明模型像商品。

## 逐项观察

### 三眼造型桌

新模型的桌面边缘更规整，嘴部由旧版浅凹贴面变为在正面和侧面均能看到的较深凹腔，手指与脚也更清楚。眼部仍需处理，灰模无法验证眼白和瞳孔。本轮没有商品纹理，不能据此判为完整外观合格。

### 椅子示例

新模型的支腿、坐垫边沿、靠背内外框和顶部卷边比旧版清楚。旧版后腿有短截、连接不清的情况；新模型多个视角可辨四条支腿。本轮仅认可这一个样本的几何试用，不认可木纹、布料或精确装饰细节，也不把官方示例的结果推广为所有家具均可用。

### 场景扶手椅

原始选区包含完整浅灰靠背，但现有 U2NetP 去背景把靠背的大部分抹掉了。两种模型实际收到的是同一张残缺前景。新模型虽能辨认坐垫和椅腿，仍有截断靠背、底部细长杂散杆件和漂浮碎片。本例明确判为失败，首先需要改进实例分割，再重新评价模型。

## 失败记录与修复

- 新模型首次运行：上游 CPU 卸载方法引用了未注册的 `components`。在适配层注册实际组件后继续实测。
- 第二、三次运行：上游分层网格细化遇到空批次，未产出可用模型。保留两个失败记录，改用完整网格查询；没有把失败尝试计成通过。
- 兼容处理同时加入条件嵌入、采样 latent 和 SDF 网格的有限值检查；记录实际检查结果，不给空网格伪造成功指标。
- 首次网页集成测试：新候选生成成功，但刷新后回到旧任务。创建成功时同步更新 URL，并在真实 Hunyuan 任务上重新验证后通过。

前三次模型失败分别保存在 `experiments/quality_20261111/alien/hunyuan/attempt_001`、`attempt_002`、`attempt_003`。网页首次失败保存在同目录实验根下的 `web_failure_001.json`，成功复测见 `web_workflow.json`。20 项 API/流程测试通过，其中使用合成网格的测试只验证传输和报告契约，**不作为模型效果证据**。

## 能与不能验收的内容

本轮可以确认：真实本地推理可运行、文件可加载、同一前景输入上的可见几何存在上述改善、网页流程可用。

本轮不能确认：真实尺寸、不可见背面、内部装配、实物材质反射、完整商品纹理。没有真实 3D 真值，因此没有编造 Chamfer、重建准确率或相似度百分比。
