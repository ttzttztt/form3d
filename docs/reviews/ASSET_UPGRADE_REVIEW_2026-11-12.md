# 资产编辑扩展、审查与验收报告 · 2026-11-12

本轮把六个方向接入现有工作台，并完成代码审查、65 项回归检查、6 个已有真实模型的编辑实测和 17 张 Blender 外部渲染。功能流程可用；高保真商品还原仍未达成。补充视图目前不参与几何融合，带 UV 网格的减面仍被保护规则拦截。

## 1. 测试范围与证据口径

- 使用已有图生模型：桌子、盆栽、杂乱室内场景沙发、柜子、彩绘花瓶；另使用已有看图编写的蒜头花瓶作为多部件资产对照。
- 本轮新增 3D 推理次数为 **0**。验证的是编辑、导出、对照、LOD、版本管理，不能据此宣称重建模型准确率提高。
- 为每个模型建立独立测试副本，保存 `test_clone_of`。原始生成模型未覆盖；已审核的历史资产不会因本轮测试自动改变审核结论。测试副本与新编辑版本均保留未验收状态。
- 使用程序生成的棋盘色彩图、平坦 OpenGL 法线图和灰度粗糙度图验证贴图通道；它们不是商品实拍木纹、布料扫描或真实面料。
- 数值来自 JSON、校验器和实际文件。未计算商品还原准确率、识别准确率、表面 Hausdorff 距离或用户操作速度提升百分比。

另做了审查后专测：静止时 WebGL draw 调用停止，旋转后恢复绘制；拟合中换版本能取消；切参考图不会沿用过期拟合；历史预览下移除参考图保留所看版本；带贴图部件减面被拦截且不发布版本、错误文字可读。详见 `review_smoke.json`。

## 4. 自动参考视角：实际结果与不足

- table：16.12% → 53.93%，128 次相机候选评估，实际掩码 96 × 41 像素。
- vase：13.84% → 72.13%，128 次相机候选评估，实际掩码 96 × 41 像素。

这两个结果来自同一次搜索前后，记录了同一参考图和模型 URL。对称物体可能从几何轮廓相近的另一侧得到较高分；材质花纹、遮挡、镜面和隐藏结构不在该指标里。桌子仍存在明显偏差，应手动调整；花瓶分数较高也不表示口部已经正确建模。65% 的界面提醒阈值只是当前提示规则，没有标注数据集验证。

相机拟合输出包括投影偏移和模型显示平移；浏览器改变大小后会要求重新拟合。重置视角会清除拟合投影与叠加。切换参考图片或模型会取消旧拟合，避免把旧数值显示成新结果。

## 5. 外部渲染与人工查看结论

Blender 5.1.2 实际导入导出的 GLB，保留材质，生成 **17 张**原版 / LOD / 局部测试贴图图像。使用每个样本相同的检查相机与原版归一化依据；这些渲染不是照片视角拟合。拼图见 `external_render_contact_sheet.jpg`，材质节点数量及源文件见 `external_renders.json`。

- 桌子：检查图中大轮廓保留，棋盘色块在局部表面可见；原版几何仍有表面细节与实际材质的缺口。
- 盆栽：叶片与枝干的大致轮廓保留；叶片厚度、表面形状与真实植物细节仍粗糙，没有新增叶片纹理。
- 沙发：减面后的主要软包轮廓和缝线仍可见；仍是原生成资产，不是对整张场景图所有家具的完整重建。
- 柜子：拱顶、隔板、门与把手轮廓仍可辨认；原材质为中性检查材质，不能当作木纹恢复成功。
- 彩绘花瓶：保留了原有预测颜色，表面粗糙和口部结构问题仍存在，不能通过商品交付验收。
- 蒜头花瓶：原版多部件与开口保留，局部底部棋盘贴图可见；整体 LOD 被保护拦截。

批量选面使用索引子集测试，不是语义标注。有些样本的测试贴图主要落在背面或小区域，不能用正面截图证明所有表面都正确贴图。浏览器桌子另以实际画笔/框选覆盖较大区域，保存为 `browser_textured_table.glb` 和截图；所有 GLB 均另外经过结构校验。

## 6. 代码审查发现、修复与覆盖

| 问题 | 修复 | 验证 |
| --- | --- | --- |
| 拆分改变 primitive 序号，旧部件 ID 可能指错 | 节点拥有稳定部件映射，新部件记录父来源 | 拆分后重命名与换材质，ID 与未拆分兄弟保持稳定；实例隔离用例 |
| 区域边界使用了整个共享 POSITION，包含未使用顶点 | 边界仅由索引实际引用的顶点计算 | 子区域重复分组失败控制 |
| 无材质模型回收后写出空 materials 数组，glTF 规范不允许 | 空集合删除键；仍保留所需资源 | 球体 LOD 原失败控制与修复后规范校验 |
| 带扩展文件跳过回收时，重复克隆产生无 UV 的旧网格，旧网格间接引用新贴图材质 | 只对真正共享实例的网格克隆；局部贴图使用正确的独立材质/属性 | 蒜头花瓶真实失败文件保留；扩展网格回归与重跑导出通过 |
| 无切线法线贴图依赖查看器临时生成 | 缺少切线时按实际 UV 补切线 | 三贴图浏览器导出 0 errors / 0 warnings |
| 补充视图与初始参考列表累加，移除后仍会回来 | 显式覆盖参考列表；UI 提供移除 | API 清空列表与浏览器删除测试 |
| 历史版本下改参考列表会让面板跳回最新版，画面与编辑对象可能不一致 | 只合并参考图信息，保留预览版本 | 历史预览删除参考图专测 |
| 拟合过程中换模型可能残留忙碌状态，换参考图可能显示旧拟合数值 | 取消信号、输入一致性检查、新模型重置忙碌状态 | 两类切换的浏览器专测 |
| 拟合相机可能被交互控制器的俯仰限制二次改变 | 约束搜索俯仰，输出完整投影信息 | 两张真实参考图重跑并记录参数 |
| 静态模型持续全帧渲染，比较视图进一步增加负载 | 相机、尺寸或选择变化时绘制 | 真实 WebGL draw 调用计数：闲置停止，旋转恢复；未宣称量化性能提升 |
| 子进程中文错误被 Windows 编码转义 | 编辑子进程显式 UTF-8 | 带 UV 的 LOD 失败控制返回可读中文 |

首次失败文件、失败日志和旧版本未删除。`lod_failure.glb` 是修复前无材质 LOD 规范失败控制，不是交付资产。蒜头花瓶首次失败记录位于测试任务 `041603c86184424db1c964e3b5ce358a`，后续成功测试使用新的隔离副本。

## 7. 版本存储与审核结论

6 个批量样本结束时，历史模型逻辑大小合计 **295,905,100 字节**，独立内容 **210,313,020 字节**，重复内容 **85,592,080 字节**。当前核对了 **41** 个文件与内容对象为同一文件的硬链接。这里是该批次存储快照；后续浏览器操作又生成了版本，不应当成此刻整个工作区的磁盘占用。硬链接不支持时会保留副本，不能把独立内容大小当成实际占用。

静态 GLB 内部回收会移除能够确认不再使用的网格、材质、纹理和 bufferView；未知扩展保守跳过。归档仅隐藏列表项，不删除图像、原模型、失败运行或历史版本。新材质、分组、LOD、恢复版本都必须独立审核，不能继承旧版通过结论。

**本轮验收结论：编辑与管理功能通过已覆盖的技术验收；本批自动生成模型没有因此通过完整商品还原验收。** 还缺语义部件识别、可靠 UV、真实多视图重建以及商品级外观核验。
