## 本次更新：TripoSR 本地自动建模

默认路线现为 `local`：裁剪/人工擦除 → 按策略分割（场景 SAM 2；透明通道保留、白底边缘分离或基础 U2NetP） → TripoSR CUDA 推理 → CPU 等值面提取 → 顶点着色 GLB → 完整校验 → 待审核。可另选 Hunyuan 几何实验。无需 API 密钥和对话介入；`assistant`、`template`、`meshy` 各自保留。

源代码固定为 TripoSR Git tree `107cefdc244c39106fa830359024f6a2f1c78871`，模型固定为 Hugging Face revision `5b521936b01fbe1890f6f9baed0254ab6351c04a`。主权重 SHA-256 为 `429e2c6b22a0923967459de24d67f05962b235f79cde6b032aa7ed2ffcd970ee`。下载脚本为 `services/workers/setup_local3d.py`，推理脚本为 `services/workers/generate_local3d.py`，后端桥接为 `services/api/local3d.py`。

3D 运行在独立 `.venv-3d` 中，和目标检测使用的 transformers 5.x 分开；本地使用 transformers 4.35.0。共享既有 CUDA torch，不修改原环境的软件。检测和生成共用显卡锁；取消会终止本任务的子进程。

当前质量边界：单件干净商品图优先。复杂背景的目标分离仍可能失败；薄杆、镂空、玻璃、镜面、文字和背面可能失真。自动输出是未校准比例模型及预测顶点颜色，不等同于精确工程模型或独立照片纹理。

本机最终验证：真实造型桌图片 43.59 秒、官方椅子示例 65.41 秒，PyTorch 显存峰值约 2,587 MiB；两个 GLB 均无校验错误或警告。网页提交、取消后继续生成、下载、刷新恢复和移动端均通过，记录为 `.data/checks/local3d-validation/result.json`。进度文件原子替换加入 Windows 临时共享锁重试，进度通知异常不再使已生成模型失败。

## 原有路线：自动识别与对话建模

对话看图建模会保存选中的参考图片，等待当前对话中的助手处理；只有真实 GLB 完成校验并导入后才显示模型。

本地 Grounding DINO Tiny 已部署，在现有 6 GB RTX 3060 上完成真实图片检测。书柜场景中检出了书柜、扶手椅、花瓶和盆栽。自动识别属于候选框检测，不等于像素级分割；用户可点击切换或手工修正。

已知难例：三眼外星人造型桌被检测为低分扶手椅，桌面出现低分落地灯候选。界面用问号提示低分标签；分数不是类别正确率。这个模型的构建来自助手对原图的直接观察，不依赖该错误标签。当前方案尚不保证任意特殊造型的自动分类正确。

无商业密钥的对话流程：上传/自动选目标 → 提交看图建模 → 在当前对话要求处理 → 助手查看图片并编写模型 → `scripts/tools/attach_assistant_asset.py` 校验和导入 → 工作台回显与下载。

对应实现为 `services/workers/detect_objects.py`、`services/api/detection.py`、`services/api/assistant_assets.py`。识别使用独立 ML 解释器，由 `VISION_PYTHON` 配置；本机复用已有环境，没有向其安装或升级软件。模型约 657 MB，缓存在 `.models/`，相同图片的检测结果可以复用。

已按两张真实上传图分别制作三眼造型床头桌和五层木书柜，输出位于 `library/models/assistant__*.glb`。源 `.blend`、实际 GLB 渲染预览和建模说明一并保留；所有尺寸均未核准。

下载默认提供 GLB；可选记录包包含模型、处理图、元数据、质量报告及可用的预览/建模说明。“记录包”用于检查依据和返工，不改变模型质量。

下文的人工选框与参数模板描述保留为原有辅助路线。当前新增状态 `awaiting_assistant` 表示等待对话协助建模，支持取消；该状态不伪造生成进度，也不自动调用商业服务。

## 已实现的闭环

```text
上传图片 → 框选一件商品 → 手工擦除背景 → 选择结构模板与尺寸
        → 生成独立 GLB → 结构检查 → 旋转查看/图片对照
        → 接受或退回 → 下载模型、处理图、元数据与质量报告
```

三类模板为开放架、桌/边几、规则双门柜。它们依据人工选择和输入参数构建，不宣称从图片自动恢复结构。原图仅作为参照和云端路线的输入证据。

## 本地实现与目标架构的差异

| 项目 | 本地 MVP | 目标生产架构 |
| --- | --- | --- |
| 业务数据 | SQLite WAL，连接逐次关闭 | PostgreSQL |
| 任务工件 | `.data/` 本地目录 | 对象存储及访问控制 |
| 任务执行 | 两线程 Worker，状态持久化 | 持久队列、独立 Worker 与分布式租约 |
| 用户 | 单人本地工作空间 | 用户/租户与权限系统 |
| 参数模板 | 直接输出规范 GLB，无需 Blender | 复杂模板、UV/烘焙可接 Blender Worker |
| 分割 | Grounding DINO 候选框 + SAM 2 自动掩码，人工框选/擦除保留 | 点提示、自动风险评估及更多真实品类验证 |
| 质量比较 | 处理图与可旋转模型并排 | 相机拟合、同角度渲染和品类检查 |
| 外部生成 | Meshy 协议适配器 | 经真实账号评测、价格与能力固定的适配器 |

选择本地实现是为了先验证用户流程和资产链路，降低首次运行的基础设施依赖。现有 Blender 参考资产独立展示为示例，不作为用户上传图片的生成结果。

## 文件与数据

```text
.data/
  workbench.sqlite3
  images/<image_id>/
    original.bin            不可变上传原始字节
    normalized.png          EXIF 纠正后的 RGBA 图
    preview.png             网页编辑预览
  jobs/<job_id>/
    prepared.png            目标裁剪与人工背景擦除结果
    mask.png                擦除掩码
    model.glb
    metadata.json
    quality_report.json
```

原图不被覆盖；手工擦除不会填补遮挡。相同图片也可创建独立任务，历史任务的输入快照不会因当前编辑变化而改变。

导出的模板坐标采用右手系、Y 向上、米制。模板参数为宽 X、深 Z、高 Y，因此 `metrics.dimensions_m` 为 `[X, Y, Z]`，即 `[宽, 高, 深]`；输入的 `dimensions` 使用有名字的宽/深/高字段。

参数未确认时明确为比例预览。用户确认尺寸只说明参数依据已确认，不证明模型每个细节正确；真实尺度 AR 始终保持关闭。云端结果不会因填写尺寸被自动拉伸，维持“未校准”状态。

## 任务与审核

- `queued/running`：执行中。
- `awaiting_review`：已有检查后的模型，需要人工查看。
- `completed`：用户接受当前候选。
- `rejected`：用户退回，需要修改参数/图片后创建新候选。
- `awaiting_input`：本地输入需要修改，或外部生成需要核对/恢复查询；按 `attention_kind` 与供应商任务 ID 区分。
- `failed/cancelled`：失败或停止本地处理。

创建接口支持 `Idempotency-Key`；相同键和相同输入返回原任务，不重复调度；相同键配不同输入返回冲突。取消后的迟到结果不能覆盖取消状态。

服务启动时重新执行未完成的本地确定性任务。已有外部任务 ID 时恢复查询；已开始云端提交但没有得到 ID 时暂停核对，不盲目重新提交。

本地线程不是分布式队列：不要运行多个 API Worker，也不要在多台服务上共享同一个数据目录。启动使用单个 Uvicorn 进程。

## 云端适配器的边界

设置 `MESHY_API_KEY` 仅表示具备服务端凭据，不表示账号已联调成功。适配器基于公开的 `image-to-3d` 提交/查询协议实现；官方文档本次访问超时，尚未调用真实账号。

外部数据传输需要在工作台显式勾选。使用处理后的 PNG，提交一次、保存返回任务 ID、查询结果并下载 GLB；HTTP 5xx 或网络中断导致提交不明确时转入待处理。

本版取消只停止本地继续处理和查询；不承诺取消供应商任务或撤销费用。无外部任务 ID 的不确定提交必须在供应商后台核对，本版不提供手动绑定供应商任务 ID 的管理界面。

仅有已知外部任务 ID 的待处理任务可以安全恢复查询。输入图片和服务端密钥不得放入前端代码。每个候选的实际价格与总账单由供应商记录；尚未实现价格同步、金额预留或严格金额上限。

云端输出如果含外部资源或未通过 glTF 检查，将拒绝作为可交付资产。尚未提供自动修复、重贴图或其他供应商回退。

## 检查与测试

GLB 首先做头部、网格、内嵌资源等基础检查；有 Node 与 glTF Validator 时执行完整规范检查，否则报告明确标记 `not_run`，不伪称已通过。

后端回归覆盖：完整审核/交付、图片裁剪与透明擦除、原图保留、并发幂等、缺少凭据、第三方处理同意、参数校验、非法图片、跨站来源、审核终态、取消后迟到结果、持久化、未知云端提交不重试，以及三类模板的尺度和面朝向。

浏览器流程覆盖：示例加载、上传、框选、背景擦除、参数录入、模型生成、图片对照、审核、交付包下载、刷新恢复、任务历史和手机窄屏。

模板规范检查与流程测试不能证明商品还原精度。下一步需要按项目方案收集真实 SKU，评测模板覆盖、云端质量和人工处理时间。
